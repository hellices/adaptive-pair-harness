# Adaptive Pair Harness v2 — 제안서 (초안)

**작성일**: 2026-09-14
**상태**: 브레인스토밍 초안. 리서치 검증 대기, 시각화·진입 UX·상태 전이 미결.

---

## 1. 개요

Adaptive Pair Harness v2는 VS Code의 Coding Agent picker에 등장하는 **실시간 공동 세션 하네스**다. 사람과 AI가 하나의 세션 안에서 키보드를 주고받으며 진행하는 페어 프로그래밍 경험을 제공하고, 그 손 바꿈의 리듬은 개인의 실력·선호에 맞춰 조정된다.

## 2. 정체성과 경계

**Adaptive Pair가 하는 일**
- 사람과 AI 사이의 **실시간 핸드오프 협상**
- 개인의 실력·선호를 관찰·축적한 **개인 프로필 관리**
- 상황에 맞는 **페어링 패턴** 선택·전환

**Adaptive Pair가 하지 않는 일**
- 저장소 도메인 지식 축적 (LLM Wiki류, 다른 스킬, 다른 하네스가 담당)
- 코드 컨벤션·아키텍처 학습 (같음)
- 작업 완료 후 PR을 자동으로 만들어 던지는 위임 흐름 (Copilot / Claude / Codex가 담당)

Picker의 기존 하네스들이 "일을 던져놓고 나중에 PR로 돌려받는" 비동기 위임 모델이라면, Pair는 **"지금 나랑 같이 시작한다"는 동시 세션 모델**이다.

## 3. 사용자 여정

1. Coding Agent picker에서 **Pair** 선택 → 위임 대신 페어링 세션 오픈.
2. Pair가 **초기 브리핑 인터뷰** — 겉으로는 작업 목표를 확인하는 질문이지만, 답변의 어휘·설계 사고 깊이·용어에서 **실력 신호를 은근히 캐치**.
3. 사용자 계정 스코프의 **실력 프로필** 로드 (GitHub Gist private). GitHub 커밋·PR 히스토리를 prior로 활용해 콜드스타트 완화.
4. 실력·작업 성격에 맞춰 **기본 페어링 패턴 자동 선택**. 사용자는 언제든 다른 패턴으로 전환 가능.
5. **실시간 세션 진행**:
   - 관찰 기반 자연 이양이 기본
   - 명시적 "네가 해봐" / "내가 해볼게" 요청은 언제든 오버라이드
   - 옵트인한 리듬(예: Ping-Pong TDD)은 정해진 지점에서 자동 손 바꿈
6. 세션 종료 시 관찰 기록을 요약해 프로필 업데이트. 원본 편집·삭제·secrets는 저장 안 함.

## 4. 핵심 컴포넌트

| 컴포넌트 | 역할 |
|---|---|
| **핸드오프 협상기** | 지금 누가 키보드를 잡을지 결정. 관찰 트리거 + 실력 예측 + 명시적 요청을 입력으로 받아 이양 이벤트를 발행. |
| **페어링 패턴 라이브러리** | 각 패턴의 트리거 규칙, 대화 톤, 시각 표현 정의. 세션 중 전환 가능. |
| **실력 프로필 저장소** | GitHub Gist(private) + 로컬 캐시. 언어·프레임워크·작업 성격별 익숙도, 선호 패턴, 페어링 히스토리 요약. |
| **세션 상태 관리자** | 세션 시작·중간·종료, 패턴 전환, 이양 이벤트 순서 보장. |
| **시각 표현 층** | 현재 패턴·손 위치·다음 이양 시점을 에디터·채팅·오버레이에 표시. |
| **소비 어댑터** | 저장소 도메인 지식·문서·컨벤션을 외부 시스템(다른 하네스, LLM Wiki)에서 읽어와 세션에 주입. |

## 5. 페어링 패턴 라이브러리 (초기 3, 리서치 검증 대기)

1. **Driver-Navigator (자연 이양)** — 가장 기본. XP 정통. Laurie Williams의 만족도·품질 지표.
2. **Ping-Pong TDD** — 옵트인 리듬. 참여 균등·집중력.
3. **Strong-Style Pairing** (Llewellyn Falco) — 두 방향:
   - **AI-Strong (Learning Mode)** — AI 시니어·사용자 손. 신입 학습에 최적.
   - **User-Strong (Teaching Mode)** — 사용자 시니어·AI 손. 고수의 설계 언어화에 최적.

Silent Observer(안티패턴), Storming(모든 세션의 초반 서브페이즈로 흡수)은 제외.

**실력 프로필 → 기본 패턴 매핑**

| 실력 | 기본 패턴 |
|---|---|
| 신입 | AI-Strong |
| 중수 | Driver-Navigator 또는 Ping-Pong |
| 고수 | User-Strong 또는 자유로운 Driver-Navigator |

## 6. 데이터 모델

- **사용자 계정 스코프 실력 프로필** — GitHub Gist(private). 사용자가 완전히 통제·편집·삭제 가능. 저장소 오염 없음.
- **세션별 로컬 캐시** — 종료 시 요약만 남기고 상세 관찰 로그는 폐기.
- **저장소 도메인 지식** — 소유하지 않음. 필요 시 외부 시스템에서 읽기.
- **프라이버시** — 원본 편집 텍스트·secrets·raw diagnostic·raw URI는 원격 프로필에 절대 저장하지 않음. 저장 대상은 **kind-level 요약**(예: "TypeScript 프로덕션 파일에서 관찰 이양 3회, 명시적 이양 1회, 이 세션 기본 패턴은 Driver-Navigator")만.

## 7. 파일 쓰기 정책 재해석

기존의 `no project-file writes`는 **정신은 유지, 문구는 재해석**:
- Pair 자체는 여전히 저장소에 함부로 쓰지 않음
- 세션 중 파일 쓰기는 **지금 손을 잡은 주체의 편집**이며, AI가 손을 잡았을 때 Pair가 대리로 쓰는 것
- 즉 사용자 눈을 통과하지 않은 쓰기는 여전히 없음
- 개인 프로필 저장소는 사용자 GitHub 계정 안이지 작업 저장소가 아님

## 8. 다른 하네스와의 관계

- 대체가 아니라 **개인화 층**. Copilot·Claude·Codex가 잘하는 걸 대체하지 않음.
- 후속 실험 여지: 다른 하네스가 생성한 코드 후보를 Pair가 개인 실력에 맞게 다시 잘라주는 라이어(rich pair)로 진화 가능. v2 스코프 밖.

## 9. 검증 트랙

- **리서치 (진행 중)**: 페어 프로그래밍 스타일별 만족도·성장·품질 근거 검증. 결과에 따라 초기 라이브러리 조정 가능.
- **사용자 테스트 (v2 이후)**: 세션 만족도, 실력 예측 정확도, 이양 시점 자연스러움.

## 10. 미결 사항

1. **손 바꿈의 시각적 표현** — 지금 어떤 패턴인지, 누가 키보드 잡고 있는지, 다음 이양 시점 예고. 브라우저 mockup 검토 유력.
2. **Picker 진입 UX** — 위임 모델 UI에 실시간 세션 진입이 어떻게 자연스럽게 들어갈지.
3. **세션 상태 전이 모델** — 시작·중간·종료·패턴 전환의 formal state machine.
4. **초기 브리핑 인터뷰의 대본 원칙** — 어떤 유도 질문이 실력 신호를 잘 캐치하는지.
5. **GitHub prior의 최소 스펙** — 커밋·PR 이력에서 무엇을 읽고, 어떻게 요약해 프로필에 반영할지.
6. **기존 확장 서피스** (`@pair` Chat participant, 인라인 코멘트)의 v2 위치 — 유지·변형·폐기 중 선택.
